# share-signal — служба связи для ссылок «без приложения»

Служба для Ogneliss Share (этап 2, `docs/WEB_P2P.md`). Получатель далеко и без
приложения: он открывает ссылку `https://ogneliss.ru/share/get/#…` в браузере, и
файлы идут напрямую с устройства отправителя по WebRTC. Чтобы две стороны нашли
друг друга, им нужен «почтовый ящик»: приложение открывает комнату, браузер кладёт
в неё предложение соединения (SDP), приложение забирает его и кладёт ответ. Эту
почту и носит служба. Сами файлы через неё не идут.

Служба маленькая: Rust, один процесс, состояние только в памяти. Тот же сервер и
тот же Nginx Proxy Manager (NPM), что у почтового сервера (`/opt/mailserver`).

## Что служба знает

| Знает (только в памяти, до часа) | Не хранит и не видит |
|---|---|
| имя комнаты — случайные 16 байт | файлы и их имена: они идут мимо службы |
| SHA-256 от секрета владельца (сам секрет не хранится) | ключ шифрования: он в ссылке после `#`, браузер на сервер его не шлёт |
| зашифрованные описания соединения (`msg` — непрозрачная строка) | содержимое `msg`: расшифровать его служба не может |
| счётчики (число комнат — в `/healthz`) | диск: на него не пишется ничего, файловая система контейнера только для чтения |
| | журнал запросов: его нет, в NPM для службы `access_log off` |

В журнал контейнера идёт по короткой строке на создание, удаление и истечение
комнаты (первые 6 символов имени) и ошибки запуска. При перезапуске службы все
комнаты пропадают.

## Установка

Сервер — тот же, где почтовый сервер и сайт: Docker, Nginx Proxy Manager
(контейнер `proxy-manager`), каталог `/opt/mailserver`.

1. Скопируйте на сервер эту папку целиком:

   ```bash
   scp -r server/share-signal root@СЕРВЕР:/root/
   ```

2. Установите:

   ```bash
   sudo bash /root/share-signal/install-share-signal.sh install
   ```

   Скрипт кладёт исходники в `/opt/mailserver/share-signal`, собирает образ
   прямо на сервере, подключает контейнер к сети Nginx Proxy Manager (общей у
   `proxy-manager` и `oauth-proxy`; другая — флагом `--network`) и ждёт, пока
   служба ответит. Первая сборка занимает несколько минут.

3. Nginx Proxy Manager (панель `http://IP-сервера:81`): хост `ogneliss.ru` →
   Edit → **Advanced** → замените раздел «Ogneliss Share» на `site/nginx-share.conf`
   из архива проекта (в конце файла новый раздел «Служба связи»,
   `location ^~ /share/api/`). Сначала скопируйте прежнее содержимое — чтобы
   вернуть при ошибке. Save.

   Адрес службы в разделе задан переменной и ищется при запросе, а не при запуске
   nginx: с литеральным именем контейнера в `proxy_pass` остановленный контейнер
   не даёт стартовать всему NPM.

4. Проверьте:

   ```bash
   sudo bash /root/share-signal/install-share-signal.sh check
   ```

   Все строки — ✓. Снаружи: `curl -s https://ogneliss.ru/share/api/v1/healthz` →
   `{"ok":true,"rooms":0}`.

## Команды

| Команда | Что делает |
|---|---|
| `install` | первая установка; повторный запуск — как `update` |
| `update` | новый код из архива, пересборка и замена контейнера (открытые комнаты теряются: обновляйте, когда нет активных раздач) |
| `check` | контейнер, ответ службы и число комнат, адрес снаружи |
| `remove` | удалить контейнер (каталог `/opt/mailserver/share-signal` остаётся) |

Флаги: `--base-url URL` (по умолчанию `https://ogneliss.ru/share/api/v1`),
`--mail-dir DIR` (по умолчанию `/opt/mailserver`), `--network ИМЯ`.

## Файлы на сервере

```
/opt/mailserver/share-signal/
  docker-compose.share.yml   создаёт установщик
  Cargo.toml, Cargo.lock, src/, Dockerfile, .dockerignore, README.md
```

Ни `.env`, ни ключей, ни каталога с данными нет: служба без состояния.
Контейнер — только для чтения, без прав (`cap_drop: ALL`, `no-new-privileges`),
пользователь `uid 10001`, порт 8789 наружу не открыт: доступ только через NPM.
Порт нельзя публиковать: при прямом доступе клиент подделал бы адрес в заголовках
и обошёл ограничение частоты.

## API (под `/share/api/v1`)

Полное описание, коды ответов и шифрование — `docs/WEB_P2P.md`, раздел 2.

| Запрос | Кто | Ответ |
|---|---|---|
| `GET /healthz` | мониторинг | `200 {"ok":true,"rooms":<число>}` |
| `PUT /rooms/{room}` + `X-Owner`, `{"ttl":60…3600}` | приложение | `200 {"expires":…}`; чужая комната — `409` |
| `DELETE /rooms/{room}` + `X-Owner` | приложение | `204` |
| `POST /rooms/{room}/offers` `{"msg":"…"}` | браузер | `201 {"sid":"…"}` |
| `GET /rooms/{room}/offers?after&wait` + `X-Owner` | приложение | долгий опрос, до 30 с |
| `PUT /rooms/{room}/answers/{sid}` + `X-Owner` | приложение | `204` |
| `GET /rooms/{room}/answers/{sid}?wait` | браузер | `200 {"msg":"…"}` или `204` |

Пределы: тело до 16 КиБ (`413`), до 10 000 комнат (`503`), 64 предложения в
комнате (`429`), 120 запросов в минуту с одного IP на `PUT /rooms` и
`POST …/offers` (`429`), всего сообщений в памяти до 32 МиБ (`503`).

## Ресурсы

- Память: в покое около 4 МиБ; сообщения в памяти не больше 32 МиБ, контейнер
  ограничен 64 МиБ. Процессор почти не нужен: ожидающие опросы — спящие задачи.
- Диск: образ около 10 МиБ (Alpine и статический бинарник); данных нет.

## Если не работает

| Что видно | Причина и что сделать |
|---|---|
| `check`: контейнер не запущен | `cd /opt/mailserver/share-signal && docker compose -f docker-compose.share.yml up -d`, журнал: `docker logs share-signal` |
| снаружи 301/302/404 | в Advanced хоста нет раздела `location ^~ /share/api/` — п. 3 установки |
| снаружи 502 | контейнер не в сети NPM: `docker network connect <сеть> share-signal` |
| снаружи нет связи | DNS или сертификат хоста `ogneliss.ru` |
| `429` от службы | больше 120 запросов в минуту с одного IP; проверьте, что NPM передаёт `X-Real-IP` (раздел из `site/nginx-share.conf`) |
