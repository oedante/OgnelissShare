# Протокол и модель безопасности

Документ описывает, как устройства Ogneliss Share находят друг друга,
связываются и передают файлы. Код — в каталоге [`rust/src`](../rust/src):
`node.rs` (соединения, сопряжение), `transfer.rs` (передачи),
`proto.rs` (сообщения), `pairing.rs` (QR-ссылка).

## Устройство и его ключ

- При первом запуске устройство создаёт ключ Ed25519 (`identity.key` в
  данных приложения). Открытый ключ — адрес устройства (`EndpointId`).
  Учётных записей, телефонов и почты нет.
- Для людей рядом с именем показывается **код устройства** — 4 знака из
  отпечатка ключа (`util::short_code`), чтобы два «iPhone» различались.
- Ключ не попадает в резервные копии Android (`allowBackup=false`,
  `dataExtractionRules`): новый телефон связывается с остальными заново.

## Соединения

Транспорт — [iroh](https://github.com/n0-computer/iroh) 1.4: QUIC с
TLS 1.3, где обе стороны доказывают владение своим ключом. Подключение
идёт **по ключу**, а не по адресу: подменить собеседника нельзя.

- Прямой путь: адреса в локальной сети, публичные адреса, пробивка NAT.
- Запасной путь: ретранслятор (relay). Он пересылает уже зашифрованные
  пакеты QUIC и видит только ключи устройств, IP-адреса, время и объём.
- Локальная сеть без интернета: поиск по mDNS (служба `_ogshare._udp`,
  кроме iOS). Устройство объявляет в сети свой открытый ключ.
- ALPN протокола: `ogneliss-share/1`.

### Шлюз: кто может подключиться

Сразу после рукопожатия TLS (`EndpointHooks::after_handshake`) входящее
соединение проверяется:

| Кто | Что будет |
|---|---|
| Устройство из «Моих устройств» или разового обмена | принимается |
| Неизвестный ключ, когда QR-код **не показан** | отклоняется с кодом 403 |
| Неизвестный ключ, когда QR-код показан | допускается «гостем» (не больше 4 одновременно): за 10 секунд он должен предъявить секрет из кода, иначе соединение закрывается |

Поэтому посторонний не может ни прислать файл, ни заспамить запросами,
ни даже узнать, что устройство с таким ключом сейчас в сети.

## Сопряжение по QR-коду

QR-код содержит ссылку:

```
ogshare://pair?v=1&m=p&id=<ключ z-base-32>&t=<секрет>&n=<имя>&p=<платформа>&r=<ретранслятор>&a=<адреса>
```

- `m` — `p` («Моё устройство», постоянная связь) или `o` (разовый обмен);
- `t` — 16 случайных байт, код действует 5 минут и **одноразовый**: первое
  предъявление секрета его погашает;
- `n`, `r`, `a` — имя, ретранслятор и прямые адреса показывающего (base64url).

Порядок:

1. Сканирующее устройство подключается **к ключу из ссылки** — значит,
   разговаривает именно с тем устройством, чей код на экране.
2. Отправляет `Pair {token, name, platform, mode}`.
3. Показывающее проверяет секрет (сравнение за постоянное время) и:
   - для разового обмена — сразу отвечает `PairOk`;
   - для «Моего устройства» — спрашивает пользователя «Подключить?» и
     показывает **проверочный код** из 4 цифр. Тот же код видит
     сканирующий. Код = BLAKE3(ключ показывающего ‖ ключ сканирующего ‖
     секрет) mod 10000. Совпали — к вам подключается то устройство,
     что у вас в руках, а не тот, кто сфотографировал QR-код издалека.
4. После `PairOk` обе стороны сохраняют друг друга (`state.json`).

«Забыть устройство» закрывает соединения с кодом 410; собеседник по этому
коду тоже убирает связь. Если он был не в сети, то узнает при следующей
попытке связаться (отказ 403).

## Сообщения

Каждый запрос — отдельный двунаправленный поток QUIC. Управляющее
сообщение — JSON с префиксом длины (4 байта, big-endian, не больше 8 МБ):

| Сообщение | Направление | Смысл |
|---|---|---|
| `hello {name, platform, version, addr}` | оба | имя, платформа, текущие адреса |
| `pair {token, name, platform, mode}` | гость → хозяин кода | сопряжение |
| `pair_ok {name, platform}` / `pair_denied {reason}` | ответ | итог |
| `offer {id, files[{path,size,mtime}], total}` | отправитель | предложение файлов |
| `offer_accept {offsets}` / `offer_decline {reason}` | получатель | ответ и смещения докачки |
| `file_hash {index, hash}` | отправитель | BLAKE3 файла после его данных |
| `complete {ok, failed[]}` | получатель | итог проверки |
| `text {id, text}` | отправитель | текст или ссылка (до 1 МБ) |

## Передача файлов

1. Отправитель собирает список (папки обходятся целиком, ссылки на папки
   не раскрываются) и шлёт `offer`.
2. Получатель проверяет пути: без `..`, абсолютных путей и пустых частей;
   символы, недопустимые в Windows/Android/macOS, заменяются на `_`;
   имена `CON`, `NUL` и т. п. получают префикс.
3. От «Моих устройств» передача принимается сразу; от разового собеседника —
   после «Принять» (2 минуты на ответ).
4. Файлы пишутся во временную папку `.ogneliss-share/<ключ>` рядом с папкой
   загрузок. Ключ = BLAKE3(отправитель, пути, размеры, времена изменения),
   поэтому повторная отправка того же самого **продолжает с места обрыва**:
   получатель сообщает в `offer_accept`, сколько байт каждого файла у него
   уже есть; целиком полученные файлы не передаются заново.
5. После каждого файла отправитель шлёт хеш BLAKE3 всего файла; получатель
   считает свой (включая ранее принятое начало) и сравнивает. Не совпал —
   файл отбрасывается и попадает в `failed`.
6. Когда всё принято, файлы переносятся в папку загрузок под свободными
   именами («фото (1).jpg»), сохраняется время изменения. Брошенные
   недокачанные передачи удаляются через неделю.

Обрыв связи посреди передачи — до трёх повторов с докачкой. Устройство не
в сети — передача ждёт его до 10 минут.

## Присутствие

Пока приложение открыто, оно держит соединение с каждым связанным
устройством (QUIC keep-alive) — отсюда «в сети / не в сети». С выключенными
устройствами связаться пробует с паузами 5, 10, 20, 40, 60 секунд. На
телефоне в фоне попытки прекращаются.

## Что хранится

| Файл | Где | Что |
|---|---|---|
| `identity.key` | данные приложения | секретный ключ устройства (права 0600 на Unix) |
| `state.json` | данные приложения | имя, связанные устройства (ключ, имя, платформа, последний адрес) |
| `.ogneliss-share/` | папка загрузок | недокачанные передачи |

Журнал (`Настройки → Журнал`) хранится только в памяти до закрытия
приложения: короткие ключи устройств и тексты ошибок (в ошибках записи
на диск может встретиться путь к файлу). Никуда не отправляется.
