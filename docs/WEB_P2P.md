# Файлы без приложения через интернет: устройство → браузер (WebRTC)

Этап 2 функции «Отдать файлы». Этап 1 — страница в локальной сети
(`rust/src/web.rs`, QR-код с адресом `http://192.168.x.x:53318/s/…`).
Здесь — получатель далеко: он открывает ссылку `https://ogneliss.ru/share/get/#…`
в любом браузере, и файлы идут **напрямую с устройства отправителя** по
WebRTC DataChannel (DTLS, сквозное шифрование). Сервер ogneliss.ru только
сводит две стороны (передаёт зашифрованные описания соединения, SDP) и файлов
не видит. Ретранслятора (TURN) нет: если обе стороны за «строгими» NAT
(часть мобильных операторов), прямой канал не установится — страница скажет
об этом и предложит открыть ссылку в той же Wi-Fi или установить приложение.

Состав:

| Часть | Где | Что делает |
|---|---|---|
| Служба связи | `server/signal/` (Rust, Docker) | почтовый ящик для зашифрованных SDP, без хранения на диске |
| Страница получателя | `site/` → `/share/get/` (HTML+JS) | расшифровывает, соединяется, сохраняет файлы |
| Ядро приложения | `rust/src/rtc.rs` (str0m) | открывает «комнату», отвечает на предложения, отдаёт файлы |

## 1. Ссылка

```
https://ogneliss.ru/share/get/#<room>.<key>
```

- `room` — 16 случайных байт, base64url без `=` (22 символа). Имя комнаты на
  службе связи.
- `key` — 32 случайных байта, base64url без `=` (43 символа). Ключ
  AES-256-GCM для сообщений через службу. Стоит после `#`: браузер не
  отправляет его на сервер, служба связи его не знает.
- Русская страница — `/share/ru/get/#…` (nginx переадресует с `/share/get/`
  по языку браузера, часть после `#` браузер сохраняет сам).

Владелец комнаты (приложение) дополнительно знает `owner` — 16 случайных байт
base64url; служба хранит только SHA-256 от него и пускает к чтению
предложений и записи ответов только с ним (заголовок `X-Owner`).

## 2. Служба связи (`/share/api/v1`)

JSON, UTF-8. Все тела ≤ 16 КиБ (иначе 413). Состояние только в памяти.
Комната живёт не дольше 1 часа после последнего `PUT`.

| Запрос | Кто | Ответ |
|---|---|---|
| `PUT /rooms/{room}` + `X-Owner`, тело `{"ttl": секунды}` (60…3600) | приложение | `200 {"expires": unix}`; комната занята другим владельцем — `409` |
| `DELETE /rooms/{room}` + `X-Owner` | приложение | `204`; чужой владелец — `403`; нет — `404` |
| `POST /rooms/{room}/offers`, тело `{"msg": "…"}` | браузер | `201 {"sid": "<12 симв.>"}`; нет комнаты — `404`; больше 64 предложений — `429` |
| `GET /rooms/{room}/offers?after=<seq>&wait=<с>` + `X-Owner` | приложение | `200 {"offers": [{"seq": n, "sid": "…", "msg": "…"}]}` — предложения с `seq > after`; если их нет — ждёт до `wait` (≤ 30) секунд и отдаёт пустой список |
| `PUT /rooms/{room}/answers/{sid}` + `X-Owner`, тело `{"msg": "…"}` | приложение | `204` |
| `GET /rooms/{room}/answers/{sid}?wait=<с>` | браузер | `200 {"msg": "…"}`; нет ответа за `wait` (≤ 30) секунд — `204`; нет комнаты или `sid` — `404` |
| `GET /health` | мониторинг | `200 ok` |

`room` и `sid` — только `[A-Za-z0-9_-]`, длина 8…64, иначе `400`. `seq`
начинается с 1. Ограничения: до 10 000 комнат (`503` сверх), до 120 запросов
в минуту с одного IP на `PUT /rooms` и `POST …/offers` (`429`), IP — из
`X-Real-IP` или первого адреса `X-Forwarded-For` (служба стоит за nginx),
иначе адрес соединения. Ответы — `Cache-Control: no-store`. Никаких журналов
с `msg`.

## 3. Шифрование сообщений

`msg` = base64url без `=` от `nonce (12 байт) ‖ шифротекст+тег` AES-256-GCM,
ключ — `key` из ссылки, nonce случайный. AAD (UTF-8):

- предложение: `ogshare-v1|offer|<room>`
- ответ: `ogshare-v1|answer|<room>|<sid>`

Открытый текст — JSON:

- предложение (браузер → приложение): `{"sdp": "<SDP offer>", "lang": "ru"|"en"}`
- ответ (приложение → браузер): `{"sdp": "<SDP answer>"}`

Не расшифровалось — сообщение молча отбрасывается (приложение) или
показывается «Ссылка неверна» (страница).

## 4. Соединение WebRTC

- Браузер — предлагающая сторона: создаёт `RTCPeerConnection` с
  `iceServers: [{urls: ["stun:stun.l.google.com:19302", "stun:stun.cloudflare.com:3478"]}]`,
  канал `createDataChannel("files", {ordered: true})`, `createOffer`,
  `setLocalDescription`, ждёт конца сбора кандидатов (`iceGatheringState ==
  "complete"`, не дольше 4 с) и отправляет `localDescription.sdp` целиком
  (без «trickle»).
- Приложение отвечает одним SDP со всеми своими кандидатами: host (адреса
  интерфейсов, IPv4 и IPv6, кроме 127/8, ::1, fe80::/10) и server-reflexive
  (адрес снаружи NAT — ответ STUN-сервера на запрос с того же UDP-сокета,
  те же STUN-серверы, что у браузера).
- Нет соединения за 20 с после ответа — страница показывает «Не удалось
  соединиться напрямую…».

## 5. Протокол канала `files`

Текстовые сообщения — JSON-команды, двоичные — данные файла.

1. Приложение, как только канал открыт:
   `{"t":"hello","v":1,"name":"<имя устройства>","expires":<unix>,"files":[{"i":0,"name":"Отпуск/a.jpg","size":123}, …]}`
2. Браузер просит файл (по одному за раз):
   `{"t":"get","i":<номер>,"offset":<байт, обычно 0>}`
3. Приложение: `{"t":"file","i":n,"size":<полный размер>,"offset":<с какого байта>}`,
   затем двоичные куски по 16 КиБ, затем `{"t":"end","i":n}`. Посылает, пока
   в буфере канала меньше 1 МиБ, иначе ждёт.
4. Ошибки: `{"t":"error","i":n,"code":"not_found"|"read"|"expired"}`.
5. Браузер: `{"t":"cancel"}` — прекратить текущий файл.
6. Браузер: `{"t":"ready"}` — если `hello` не пришёл за 1 с после открытия
   канала (Chromium иногда теряет сообщение, посланное в момент открытия),
   повторяется раз в 2 с; приложение отвечает новым `hello`.

Приложение считает скачивание, когда отправило `end` для всего файла с
`offset` 0, и шлёт событие `{"type":"web_download","share":<id>,"name":…}` —
как этап 1. Одновременно — до 4 получателей на раздачу. Раздача
остановлена или истекла — приложение закрывает соединения и удаляет комнату
(`DELETE`).

## 6. Страница получателя

- Без сторонних скриптов, всё в одном HTML (стиль — как у страницы этапа 1:
  синий #1D4F91, карточки, светлая и тёмная тема).
- Состояния: «Подключаемся к устройству…» → список файлов с кнопками
  «Скачать» и «Скачать всё» (файлы по очереди) → ход загрузки (байты,
  скорость, отмена) → «Готово». Ошибки: ссылка неверна или устарела;
  устройство не отвечает (раздачу остановили, приложение закрыто);
  не удалось соединиться напрямую (советы: открыть в той же Wi-Fi, другой
  сети, установить приложение — ссылка на `/share/`).
- Сохранение: если есть `showSaveFilePicker` — запись потоком прямо в файл;
  иначе куски копятся в памяти и сохраняются как `Blob` (у файлов больше
  1 ГБ — предупреждение «лучше открыть ссылку на компьютере»).
- Языки — русский и английский (две страницы из `build_share_site.py`).
